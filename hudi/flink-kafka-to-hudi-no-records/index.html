Flink 读取 Kafka 消息写入 Hudi 表无报错但没有写入任何记录的解决方法

原创付费分类：Hudi发表于：2024-01-31阅读用时：7 分钟 (约 1041 字)阅读：0

本问题发生的场景是：使用 Kafka Connect 的 Debezium MySQL Source Connector 将 MySQL 的 CDC 数据 （Confluent Avro 格式）接入到 Kafka 之后，通过 Flink 读取并解析这些 CDC 数据，然后写入到 Hudi 表中。在测试过程中发现：启动写入作业后，Hudi 表中迟迟没有数据写入，而 Flink 作业也没有报错。实际上，这应该是一比较常见的问题，我们的测试环境并没有特别的配置，大多数初次进行集成的开发者，大概率都会遇到这一问题，本文将详细介绍一个该问题产生和原因和解决方法。

1. 触发写入操作提交的“秘密”

实际上，Flink 以流式读取 Kafka 消息，向 Hudi 写入数据时，在默认的配置下，就是不会将任何记录持久化到 Hudi 表中的，这其实是一个默认行为。我们来看一下表现，以下是执行了 insert into my-hudi-sink-talbe select ... from my-kafka-source-table 这样的 SQL 后，Flink Job Manager 页面上的情况：

Kafka Topic 中已经有 69 条 CDC 数据了，从上图也可以看到，作业成功地读取到了 69 条记录，过程中也无任何报错，然后整个 Job 就一直这样运行着，在 Hudi 表对应的存储目录上，一个数据文件也没有。

导致这一问题的关键原因是：**Flink 和 Hudi 集成的实现：Flink Hudi Connector 采用了这样的设计：当 Flink 流式读取 Kafka 中的消息并写入 Hudi 表时，触发写入操作进行提交的条件是：到达了检查点 Checkpoint ）！**如果我们全程使用的是 Flink SQL 操作，那么，在不显式配置的情况下，Flink 是不会启用 Checkpoint 的，所以，也就永远不会触发实际的提交动作，因此 Hudi 表中不会有任何“落地”的记录，这就是 Root Cause！我们看一下以两篇官方文章对该情况的解释：
