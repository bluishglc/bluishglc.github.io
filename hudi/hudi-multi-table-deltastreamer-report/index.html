Apache Hudi HoodieMultiTableDeltaStreamer 多表接入 CDC 数据测试报告和结论

原创付费分类：Hudi发表于：2023-07-16阅读用时：8 分钟 (约 1220 字)阅读：0

首先，强调一下测试环境：本次测试是在AWS EMR Serverless EMR 6.10 和 6.11 两个版本上进行的，对应的Hudi版本是 0.12.2 和 0.13.0 ，该测试的结论在同版本的 开源 Spark和Hudi上不一定成立，请知悉。其次，在同一测试环境下，单表的 CDC 数据接入已经测试完毕并发表在 《CDC 实时入湖方案：MySQL＞Kafka Connect＞Kafka ＆ Schema Registry＞Hudi ( HoodieMultiTableStreamer ) 》 一文的 5.1 一节，多表接入的细节在该文中也有记录，但只是在 Hudi 0.14.0 版本上，本文是汇总了近期三个 Hudi 版本的测试结果。重要结论如下：

1. 重要结论

本次测试围绕 HoodieMultiTableDeltaStreamer 在 Hudi 0.12.2（EMR 6.10）、Hudi 0.13.0（EMR 6.11）、Hudi 0.14.0（EMR 6.15) 三个版本上进行了反复测试，测试结果如下：

  • 在 Hudi 0.12.2（EMR 6.10）上报错： org.apache.avro.AvroRuntimeException: Malformed data. Length is negative: -50

  • 在 Hudi 0.13.0（EMR 6.11）上报错： HoodieException: Commit 20230714121640329 failed and rolled-back !

  • 在 Hudi 0.14.0（EMR 6.15) 上报错： java.lang.IllegalArgumentException: Property hoodie.streamer.schemaprovider.registry.schemaconverter not found ，补充该配置 hoodie.deltastreamer.schemaprovider.registry.schemaconverter=org.apache.hudi.utilities.schema.converter.JsonToAvroSchemaConverter 后，报错信息为 org.apache.hudi.exception.HoodieKeyException: recordKey value: "null" for field: "order_number" cannot be null or empty. 理论上，不应该配置 org.apache.hudi.utilities.schema.converter.JsonToAvroSchemaConverter ，根据官方文档的说法，这个 converter 是在把 Json 数据写到 Avro 格式的 Hudi 表时才会配置的，我们这里的测试不是这种情况，所以不应该配置。此外，还有一种改法是：将这个配置项置空： hoodie.deltastreamer.schemaprovider.registry.schemaconverter= ，此时的报错是：java.lang.NullPointerException: null value for (non-nullable) Source at Envelope.source。 关于这三种配置的测试请参考 《CDC 数据入湖方案：Kafka Connect＞Kafka + Schema Registry＞Hudi ( HoodieMultiTableStreamer ) 》 5.2 节的三个测试。

目前看：配置错误的概率极小，应该就是HoodieMultiTableDeltaStreamer自身的问题了，从各方面调研的情况来，HoodieMultiTableDeltaStreamer的使用者很少，所以存在Bug的可能性很大。目前已经发现的一个Bug是：–config-folder必须配置为s3://bucket-name//，在末尾处必须添加//，因为从输出的日志可以看到，Hudi在拼接目录时中间就是会丢掉一个/，所以只能在folder路径上提前补一个！
