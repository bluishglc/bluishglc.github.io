Python 环境构建最佳实践：Mamba + Conda + PIP

原创付费分类：Python发表于：2023-10-18阅读用时：12 分钟 (约 1806 字)阅读：0

此前，我们单独介绍过 PIP 和 Conda，在后续的实际应用中，还是遇到了不少 Python 环境构建的问题，特别是在 Windows 系统上，最突出的表现是：虽然PIP的包依赖解析和下载都很快，但在 Windows 上经常会因为缺失底层依赖的程序库（例如某些dll文件）而导致 Python 程序启动时报错，此时，改用 Conda 通常可以解决此类问题，但是，Conda 的问题在于：它的包依赖解析问题很大，耗时很长，解决 Conda 这一问题的方法是引入 Mamba，Mamba 可以视作是 Conda 的一个改进版本，它的使用方法（命令和参数）与 Conda 完全一致，它并没完全重写 Conda，而是重点改进了 Conda 的包依赖解析和下载功能，解决了前面提到的痛点。此外，Mamba / Conda 的 Channel 未必能提供程序依赖的所有包，此时还需使用 PIP 来安装这些包，所以，目前来看：Mamba + Conda + PIP 是在 Windows 系统上构建 Python 环境比较理想的一种组合。

本文以 https://github.com/alejandro-ao/ask-multiple-pdfs 这个项目为例，介绍一下使用 Mamba + Conda + PIP 构建其环境的全过程。ask-multiple-pdfs 是一个简单的 LLM 应用，对于新手来说，在 Windows 上构建这个项目并不是一件简单事情。虽然项目中提供了 requirements.txt 文件，使用 PIP 可以完成全部包的安装，但是在 Windows 下启动程序时，会报一个 ModuleNotFoundError("No module named 'faiss.swigfaiss_avx2'") 错误，原因就是前面提到的，在本地 Windows 系统上缺少某些底层程序库导致的，类似的问题在 Windows 上很常见，要么是找到缺失的库，在系统上单独安装对应的 Windows 版本，要么是使用 Conda 搞定这些繁琐的问题，由于此类问题较多，且在这些问题上花费时间是没有意义的，所以选择 Conda 是比较明智的， 但是当我们使用：

1. 安装 Mamba

Mamba 的安装可参考官方文档： https://mamba.readthedocs.io/en/latest/mamba-installation.html#mamba-install ， Mamba 有两种安装方式：一种方法是在没有安装 Conda 的情况下直接安装，这种方式称为 Fresh Install ；另一种是在安装了 Conda 的前提下，使用 conda install -y -n base conda-forge::mamba 来安装，这种方式称为 Existing conda install ，Mamba官方文档建议使用第一种方式。从个人的测试情况看，确实使用第一种方式是更明智的，因为使用第二种方式安装后，在使用 mamba 命令时会遇到一个 consider using the --no-plugins option to turn off plugins 错误。

使用 Fresh Install 方式安装非常简单，首先移除此前安装的 Conda，然后去 https://github.com/conda-forge/miniforge 下载 Mamba 的安装包：Miniforge，Miniforge 就是配置好的 Conda + Mamba 的安装包，并将 Conda 的 Channel 预设为了 conda-forge，所以只需安装 Miniforge，我们就可以完成 Conda 和 Mamba 的安转了，非常简单。

2. 测试 Mamba
