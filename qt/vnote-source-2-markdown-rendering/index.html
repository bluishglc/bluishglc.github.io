GitHub 1.2 万星 Qt 项目 VNote 源码解读(二)：Markdown 文本渲染

原创付费分类：Qt发表于：2026-03-31阅读用时：42 分钟 (约 6277 字)阅读：0

VNote 的 Markdown 文档是使用 QWebEngineView 这个组件来展示的，这是一个基于 Chromium 内核的浏览器组件。在 Qt 下展示 Markdown 文档，QWebEngineView 可以说是最好的选择。因为 Markdown 实质上是 HTML，可以认为是面向写作排版设计的简化版 HTML，并且围绕 Markdown 的渲染（公式、图表、代码块等），在 JavaScript 生态里已经有了大量的库和组件来处理相关内容，而使用 QWebEngineView 的话就可以复用 JavaScript 生态下的这些资源。但使用这些 JavaScript 组件的过程中需要和后台其他的 C++ 组件交互，例如：把后台读取的 Markdown 文本传递到前台，为此 Qt 提供了负责前后端通信也就是 JavaScript 和 C++ 互操作的组件：QWebChannel，如果要把 Markdown 的渲染过程理解透彻，必须要熟知 QWebChannel 的工作原理，具体可参考 《Qt 前后端通信(QWebChannel Js / C++ 互操作)：原理、示例、步骤解说》 一文。此外，建议最好先阅读本系列的第一篇文章 《GitHub 1.2 万星 Qt 项目 VNote 源码解读(一)：核心类与主流程》 一文，以便对 VNote 的整体设计有一个背景性了解。

VNote 的 Markdown 文档渲染可以分为：加载 HTML 文档、加载 Markdown 原生文本、渲染 Markdown 原生文本三个阶段，具体的操作流程见下图：

3. 渲染 Markdown 原生文本

3.1 整体逻辑

下图右侧是原始的 HTML 模板文件，左侧是测试文档渲染成 HTML 的内容，它是被 window.vxcore.setMarkdownText(p_text) 转换为 HTML 片段中加入到 <div id="vx-content"></div> 中的：

setMarkdownText 方法是 MarkdownViewerCore 的一个成员方法，这个 类 内部维持着 workers 、 numOfOngoingWorkers 、 pendingData 几个重要的字段，它们在 setMarkdownText 的执行过程中起着非常重要的作用。在介绍这个方法前，需要先介绍一下负责渲染 Markdown 原生文本的主要组件：VxWorker 类和它的子类。在 VNote 的前端设计中，所有与 Markdown 渲染相关的“专项任务处理类”都继承了 VxWorker 类，例如：负责把 markdown 文本转换成 html 的 MarkdownIt，负责将各种用 markdown 语法描述的 公式、流程图转换为真实公式和图表的 MathJaxRender，Mermaid 等，它们都是 worker：

这些 worker 实例化后都会通过 vxcore 的 registerWorker 方法添加到它的内部的一个 map 中。这些 worker 在自己的 registerInternal 方法中会注册自己会响应什么信号，注意，worker 注册的信号都是 Js 发出的前端信号，不是后端 Qt 的信号，当这个信号发出时，它们就开始属于自己职责内的渲染工作。

虽然有 8 种负责渲染不同内容的 Worker，但它具只注册了两种信号（都是前端 Js 信号）： markdownTextUpdated 和 basicMarkdownRendered ，前一种由 MarkdownIt 负责响应的，后一种是所有其他 worker 要响应的。在这里，VNote 设计的逻辑是：每次文本更新时（即 setMarkdownText("…") 执行时），总是先触发 markdownTextUpdated 信号，让 MarkdownIt 先工作，等它工作完再发射 basicMarkdownRendered 信号，让其他 worker 再开始工作。因为只有先通过 MarkdownIt 生成出 HTML/DOM，后续其他 Worker 才能在 DOM 基础上继续渲染公式、图表、代码块。

3.2 实现细节

现在，我们来看一下 setMarkdownText 的具体实现：

每次变更文本都会触发这个方法，每次“更新”都是这“同一套流程”：首先检查 numOfOngoingWorkers 是否已归零，如果没有，说明上一轮渲染工作还没有结束（上一次 setMarkdownText 方法还没执行完），此时，只是简单的把后端传过来的文本放到 pendingData.text 里暂存，然后就退出了，这条逻辑分支实际上是为应对“高频输入”而设计的，当用户高频修改文档时，前端页面会来不及渲染，VNote 采取的应对策略是：后台每传送一次新文本就放到 pendingData.text 里暂存，如果前一次存放的文本还没有被处理，那就用这一次的新文本直接“覆盖”，等到新一轮渲染启动时，总是以用户最后也是最新的输入为准，也就是 Last Write Wins 模式。这里有一个非常重要的细节，你可能会觉得意外： 用户每一次修改文本，即使只改了一个标点符号，VNote 也是将整个文本重新发到前端去渲染的 。这也是为什么 pendingData.text 每次都是直接覆盖而不是累加的原因，因为 VNote 没有使用增量更新，而是每次改动都会重新加载整个文档再次整体渲染 ！

如果 numOfOngoingWorkers == 0 ，表明当前无渲染作业，可以开始渲染，首先：将计数器 numOfOngoingWorkers 置为所有 workers 的数量： this.numOfOngoingWorkers = this.workers.size ，表示所有 worker 都已进入工作状态，然后发送 markdownTextUpdated 信号（前台到前台的信号），响应这个信号的是 MarkdownIt 这个 worker 的 render 方法:

这个方法会将普通的 markdown 文本渲染成 HTML（参考 《附录 4.3 经 MarkdownIt 渲染后的文本》 ），然后 把这部分内容添加到 <div id="vx-content"></div> 中。然后调用 finishWork 方法，将计数器 numOfOngoingWorkers 减一。
