GitHub 1.2 万星 Qt 项目 VNote 源码解读(七)：In-Place Preview 模式

原创付费分类：Qt发表于：2026-05-07阅读用时：12 分钟 (约 1842 字)阅读：0

VNote 支持 In-Place Preview 模式，可以翻译成：原地预览模式，就是在编辑窗口中，在图片、公式、图表、流程图代码的下方直接渲染出图形效果，目的应该是在纯编辑模式下也能及时看到需要效果，便于随时发现代码错误或调整内容。这个模式和 Typora 的即时渲染模式还不太一样，一个只它只渲染公式、图表、流程图这些需要在编辑过程中即时反馈效果的部分，另一点是它会同时显示代码和渲染效果，Typora 的即时渲染是一边编辑一边就渲染了，不会展示原生文本。

此外，这将是本系列的最后一篇文章，本文也没有把 In-Place Preview 模式介绍完。回看这个 基于 Qt 开发的 Markdown 编辑器 ，尽管经过多年的积累，它的功能已非常丰富，但难掩它在技术上的一种“陈旧”感，这种感觉主要来自于 C++，当我们去看一些使用新型语言（如 Rust）实现的同类型工具时，这种感觉尤为强烈。此外，关于 VNote 这个项目本身而言，有不少地方的设计都有改进的空间。当我最初发现它使用全量更新的方式去渲染文本时，老实说，和我的期望是有落差的。最后，还是希望这个软件能一直走下去。

1. 实现原理

VNote 的 In-Place Preview 模式是一个看似“神奇”，实则“直白”，执行链路“复杂”的过程：

  • 看似“神奇”：不同于 MarkdownViewer（一个 QWebEngine）可以自已渲染各种图表和公式，MarkdownEditor 作为一个 editor 是没有渲染能力的，但它确实能呈现图表和公式，这是为什么说它“神奇”；

  • 实则“直白”：MarkdownEditor 呈现图表和公式的方法其实是把它们的原始 Markdown 文本传送到了 MarkdownViewer 对应的前端 Js 环境进行渲染的，然后把渲染出的图片数据 set 回 adapter，后端就可以拿到渲染后的纯图片数据了，然后 MarkdownEditor 实际嵌入的是这个从前台获取的静态图片；

  • 执行链路“复杂”：完成上述过程要跨越前后台多个 C++、Js 类，使用了多次信号发射和响应，整个执行链路冗长且极其隐匿（不直观）（这会部分实现有待改进）
