GitHub 1.2 万星 Qt 项目 VNote 源码解读(六)：加载和渲染 Markdown 文本时的同步机制

原创付费分类：Qt发表于：2026-05-04阅读用时：21 分钟 (约 3138 字)阅读：0

在 VNote 中打开和编辑一个 Markdown 文档时，有两个“敏感”阶段：一个是在打开文文档时加载 HTML 模板（关键是初始化 js 环境），另一个是在打开或编辑文档时，加载 Markdown 原生文本并渲染，在这两个操作执行期间，很多其他操作是不能执行的，这就需要一些同步机制来控制它们之间的执行顺序。导致在这两个“敏感”阶段需要阻塞某些操作的原因是不太一样的：

  • 加载 HTML 模板（关键是初始化 js 环境）时阻塞后台操作的原因：

加载 HTML 模板时需要根据 m_ready 是否为 true 来决定要不要阻塞大部分的后台 C++ 操作，因为：加载 HTML 模板时会引入大量 Js 文件并执行一些 Js 初始化操作，很多后台 C++ 操作需要前台页面的响应，在 Js 环境没就绪，也就是 HTML 模板没有加载完毕时，是不能执行这些操作的

  • 加载 Markdown 原生文本并渲染时阻塞后千操作的原因：

加载 Markdown 原生文本并渲染时需要通过一个计数器 numOfOngoingWorkers 是否大于 0 来决定要不要阻塞一部分的前台 Js 操作。当 numOfOngoingWorkers > 0 时表示当前页面正在渲染中，此时会阻塞部分 Js 操作，因为：在加载 Markdown 原生文本并渲染的过程中会填充和改动 HTML 页面，部分 Js 操作需要依赖填充或改写后的 HTML 元素才能工作（例如：scrollToLine() 依赖的行号属性 data-source-line ）

而当它们完成后，放行阻塞操作的方式也是不一样的：

  • 加载 HTML 模板（关键是初始化 js 环境）完成后的放行操作：

HTML 模板页面会回调后台的 setReady(true) 方法，将此前封装成 action 并缓存在 m_pendingActions 队列中的操作一一取出并“回放”

  • 加载 Markdown 原生文本并渲染完成后的放行操作：

Markdown 原生文本并渲染完成后会在 finishWorker() 里“补充执行”一次setMarkdownText() 或 scrollToLine()，使用的 text 和 linenumber 等参数是缓存的最后一次传入的值（last-write-win)
