上图来自于美国布朗大学编纂的 《The Rust Programming Language》 一书的 《4.2 References and Borrowing》 一节，这本书和 Rust 官方的那本 《The Rust Programming Language》 同名，是在官方版本的基础上推出的一个“加强版”，其中一个突出的亮点就是全书大量使用了上面那种带标注的配图。这些标注其实是通过一个叫 Aquascope 的 开源工具 自动生成的，这是一款专门为 Rust 程序生成可视化标注的工具，它生成的这些标注反映的是 Rust 编译器对一段代码的真实分析过程，是对 Rust 借用检查工作方式最真实的呈现，就像这个工具在 Github 上对自己的介绍一样： Look Beneath the Surface of Rust ！这让网上那些试图通过各种比喻或个人理解去解释借用检查机制的文章都没有了“说服力”，而作为学习者，我们应该学习和使用最真实准确的理论和方法，免得以后“走火入魔”，而这个标注系统就是“Rust 借用检查”这个知识领域里我们最应该掌握的工具和方法论。

如果我们翻阅布朗大学的这本 《The Rust Programming Language》 ，你会发现，在一本如此倚重这个标注系统进行讲解的图书里，它对标注符号的解释可以说是“惜字如金”，反复阅读之后还是满脸问号，如果搜索互联网，你会发现相关的资料很少，这也决定了 AI 不会给到我们太多助力。其中原因除了 Aquascope 这个工具本身没有提供完备的文档外，我觉得最大的原因是：这些符号本身就很难解释，其中一些符号折射出了很多 Rust 的底层机制，想解释清楚并不容易，更困难的部分不是符号本身，而是符号前后的变化，可以说 Rust 借用检查的“全部秘密”都藏在了这些符号的前后变化中 ，这也是我们决定要撰写这篇啃下这块硬骨头的原因。（友情提示：阅读本文需要对 Rust 所有权和借用检查有基本的了解，如有必要可参考 《深入理解 Rust 所有权》 一文）

摘要

本文深入解析了 Rust 借用检查的底层权限模型，通过 Aquascope 工具生成的权限标注系统，揭示了编译器如何通过 R（读取）、W（写入）、O（拥有）三种权限标志位来实施借用规则。文章详细阐述了：

  1. 值的权限 ：R、W、O 权限如何映射到借用规则，以及它们如何随引用创建/失效而动态变化

  2. 引用的权限 ：引用自身也拥有 R、W、O 权限，与所引用的值权限相互独立

  3. 解引用的权限 ：解引用权限记录”通过引用访问目标位置时能获得的权限”，是定义引用时两层语义中的关键一层

  4. 位置与访问路径 ：权限附着在访问路径而非目标位置上，解释了为何同一内存位置的不同访问方式可能拥有不同权限

通过完整示例解读，展示了权限模型如何精确描述借用检查的实时状态变化，为理解 Rust 所有权系统提供了编译器视角的底层洞察。

1. 认识权限模型

权限模型是 Rust 借用检查的底层支撑，编译器在进行借用检查时，会解析并推导每一个值和引用是否拥有读取、写入和所有权限来判断借用行为是否合法。我们以前知晓的一些借用规则，例如：值借出一个可变引用后便不能再借出任何其他引用或值借出一个不可变引用后便不能在借出任何可变引用，这些规则最终都是以权限的形式在值和引用身上表达的。Rust 的权限模型把值或引用（准确地说是一个“place”(位置），后面会解释）的权限分成三种：

  • 读取（ R ）：数据可以复制到其他位置

  • 写入（ W ）：数据可以被修改

  • 拥有（ O ）：数据可以移动或删除

此外，对于一个变量，它还可能有四种与权限变更有关的状态：

  • ⮥ ：获得权限（一般发生在刚初始化时）

  • ⮧ ：失去所有权限（一般发生在生命周期终止时）

  • 🡪 ：部分权限被借用（部分全权临时丢失，一般发生在一个值创建了引用之后）

  • ⭯ ：重新恢复权限（一般发生在一个值的所有引用全部消亡后，值还存在时）

由于值和引用的本质不同，它们的三种权限表达的具体含义也有所差异，下面我们来详细介绍一下。

2. 值的权限

我们先来介绍值的 R、W、O 权限。对于一个值来说，它的读取、写入、所有权似乎是最容易理解的，但是，值的 R、W、O 权限其实蕴藏着更深刻的借用检查规则，而借用规则又反向决定着一个值的 R、W、O 权限，两者相互依存，相互协作。我们说：一个值“可读”通常意味者这个值可以出现在等号的右侧或作为参数传给调用函数亦或是接收一个函数的返回值，这是一个值“可读”最直观的体现，在 Rust 里“可读”发生了一些“根本性”的变化，首先，值出现在等号右侧的时候已不再单纯地表示它可读了，而是发生了所有权的转移（如无特别说明，本文所说的值均指非 Copy 类型），这一点相信你应该已经很清楚了，下面的示例演示了这一点：
