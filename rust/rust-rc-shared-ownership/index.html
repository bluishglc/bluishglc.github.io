所有权是 Rust 最核心也是最基础的概念之一，可能在一开始接触时会觉得有一些困难，但经过认真学习后基本都可以掌握。不过，这并不意味着我们就理解透彻了，在遇到一些复杂场景时，很多人会再次陷入到困惑中。最近，我在试图理解“为什么 Rc 类型跨线程 move 是不安全的”这样一个问题时，就掉进了“共享所有权”的逻辑陷阱中，浪费了不少时间，究其原因还是对值和所有权的认识不够深刻导致的，所以我特意撰写了这篇文章把“共享所有权”这个问题解释清楚。此外，推荐本博客近期讨论 Rust 多线程的精华文章： 《无为而治，Rust 多线程的处世哲学》 、 《万物皆可多线程？深入解读 Rust 的 Send 和 Sync》 、 《Rust 语言特性：多线程和并发编程》

1. 回顾：变量名 / 值 / 资源

首先，钉死概念：

概念 解释 所处位置
变量名（绑定） 一个名字，用于在编译期指代一个“值” 编译期概念，运行时不存在
值 对应某种类型的数据，从编译期就存在，靠类型“占位”，编译期时是语义上的“实体”，进入运行期后，值就是内存中的一串字节 (通常在）栈上
资源 值所管辖的数据，但不在值的字节里，而是通过指针建立关联 (通常在）堆上

1.1 变量名（绑定）

“变量名”是本文采纳的称谓，在 Rust 里，它的官方称谓叫“绑定”（Binding），一个很怪异的名字，是吧？以上面的代码为例，标准的表述是： s 是一个 String 类型的值的“绑定”，或者说是： 名字 s 被绑定到了一个 String 类型的值上 。“绑定”不是 Rust 独创的概念，它其实是 编译原理 里的一个术语，这里之所以不把 s 称为“变量”是因为：长久以来，传统语言将“变量”的概念固化成了“一个可以随时改变存放内容的 内存 位置”，这对 Rust 来说不太贴切，因为 Rust 定义的“变量”有可变与不可变之分，但这其实算不上是个问题，由于长期的使用习惯，叫“变量”没有任何问题，大家都能理解。

关于变量名（绑定）要特别注意的是：在源代码中出现的变量仅仅是一个“名字”，是只存在于编译期的一个“符号”，用于在编译期指代一个值，一旦完成编译，这个“名字”将不复存在，也就是不会出现在机器码中。在运行时，程序会使用一个栈内的偏移量去找到那个值，根本不需要这个“名字”。
