Rust 语言特性：内部可变性（关于 Cell＜T＞ 和 RefCell＜T＞）

原创分类：Rust发表于：2026-06-12阅读用时：17 分钟 (约 2613 字)阅读：0

Rust 对不可变引用和可变应用进行了严格的区分，但有时候，我们需要在一个不可变的整体中获得某一个部分的“可变”引用，以方便执行某些操作，特别是当我们非常确定这种局部的可变性不会危害到内存安全时，我们需要 Rust 语言给我们一个“特别许可” 允许我们这样去做，这正是 Cell<T> 和 RefCell<T> 两种容器类型（也可以认为是一种智能指针）提供的功能。真诚推荐本博客近期的两篇精华好文 《你真得懂 Rust 借用检查吗？一文聊透 Borrow Checker 底层逻辑：权限模型》 和 《深入理解 Rust 生命周期（可能是全网最透彻的解读了）》

2. 关于 Cell 的更多信息

在上一节的简单示例中，我们只是初步认识了 Cell<T> ，本节继续深入了解一下。 Cell<T> 的官方文档是： https://rustwiki.org/zh-CN/core/cell/struct.Cell.html 。 Cell<T> 的一大特点是：绝不暴露它包裹的值！即使你看到我们可以通过它的 get() 和 set() 方法去读写它内部的值时，也不是把它内部的值“暴露”出来，而是直接发生了内部包裹值的整体替换、移动或复制 。 Cell<T> 对内部包裹值的处理可以分成三种情况：

  • 将内部值复制出来

    • 例如： Cell<T: Copy>::get()

  • 将内部值替换出来

    • 例如： Cell<T: Default>::take() 🠚 取出内部值，并以该类型的默认值进行填充（例如 i32 默认值是 0)

    • 例如： Cell<T>::replace() 🠚 取出内部值，并用指定的值填充回去

  • 将内部值取出，同时将所有权也 move 出来，即：这会导致 Cell 失效

    • 例如： Cell<T>::into_inner() 🠚 取出内部值，且内部值的所有权也一并 move 了出来，Cell 将失效

关于 Cell<T> ，网上有一种非常肤浅的认识，认为： Cell<T> 是专门针对 Copy 类型的，它执行的是 copy 语义！这个认识是不准确的，因为上面的示例已经说明它除了 copy 之外，还可以 replace 或 move。 Cell<T> 设计的关键立足点是：不对外暴露值 ！

3. 另一种内部可变性容器 RefCell

与 Cell<T> 相近的另一种内部可变性容器是 RefCell<T> ，它同样可以在不声明 mut 的情况下去改写它包裹的值，但它是通过引用去改写值的，而且它还能对外借出包裹值的可变引用，而不像 Cell<T> 那样是直接复制或替换值本身。还是通过一个示例来解释：

  • 使用 replace() 方法直接改写值
  • 使用 replace_with() 方法执行闭包逻辑改写值
  • 使用 borrow() 借出不可变引用
  • 使用 borrow_mut() 借出可变引用

要特别提醒注意的是： RefCell<T> 在借出引用时依然会严格遵守借用规则，即：只能借出一个可变引用或多个不可变引用，不允许同时借出可变引用和不可变引用 。此外， RefCell<T> 的另一个显著特点是：它是在运行时进行借用检查的，而不是在编译时，这一点非常独特！

4. Cell 和 RefCell 的异同

介绍完两种内部可变性容器后，我们来梳理一下它们之间的异同：

异同点 Cell<T> RefCell<T>
对值的操作方式 对内部值的修改不是通过获得内部值的引用进行的，而是通过复制、移动、替换整个值来完成的。 对内部值的修改是通过引用完成的，且可以对外借出值的可变引用（也包括不可变引用）
执行借用检查的时机 编译期 运行期
