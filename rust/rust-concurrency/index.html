Rust 语言特性：多线程和并发编程

原创分类：Rust发表于：2026-08-19阅读用时：40 分钟 (约 6044 字)阅读：0

Rust 的多线程机制与其他语言有很大的不同，原因在于：Rust 能靠所有权和类型检查（特别是借用检查）在编译期就能检查出部分潜在的线程安全问题，而不像其他语言那样，只能在运行期通过并发测试去重现 bug，Rust 特意把自己这种“在编译期靠所有权和类型检查（特别是借用检查）就能识别出潜在的部分线程安全问题”的能力称为“无畏并发”。推荐本博客近期讨论 Rust 多线程的精华文章： 《无为而治，Rust 多线程的处世哲学》 、 《万物皆可多线程？深入解读 Rust 的 Send 和 Sync》 、 《Rust 所有权进阶必读：为什么 Rc 共享所有权是个伪概念？》

有趣的是，关于这一点，早期的 Rust 开发团队也没有意识到。最初，Rust 引入所有权和借用检查时，仅仅是为了确保“内存安全”，但是，随着时间的推移，团队发现所有权和类型系统同样能规避一部分的“线程安全”问题（例如：数据竞争问题）。此外，就像 Rust 在其他方向上的实现风格，Rust 将一些线程安全的规则直接编写进了类型系统中，使用这些类型会直接带上特定的线程安全“语义”，这些因素一起造就了 Rust 独一无二的并发编程机制。注：本文内容以 The Rust Book 第 16 章内容为蓝本进行了注解和补充。

2. 使用 join

4. 线程间通信

Rust 的线程间通信使用的是 channel 模式，这在很多编程语言中也都有。在这个模式中，负责发送消息的对象称为 transmitter ，简写为 tx ，负责接收消息的对象称为 receiver ，简写为 rx 。它们将分属两个线程（使用 move 将其所有权移动到闭包中），发送者所处的线程可以通过 transmitter 的 send() 方法向外发送消息，接收者所处的线程可以使用 receiver 的 recv() 方法接收消息，这个模式简洁清晰，很容易理解。

这里，我们要特别解释一下 transmitter 这个称谓，实际上，如果我们查看一下 Rust 文档你就会发现，我们在 Rust 经常提及的这个 tx 其实它的类型是 Sender<T> ，并没有 Transmitter<T> 这种类型，那为什么 Rust 还是管消息的发送方叫 transmitter 或 tx 呢？这是因为 tx 和 rx 已经成为了约定俗成的术语，它们最初来源于早期无线通信领域，一般 tx 指代电报发送方， rx 指代电报接收方，这种命名习惯又被应用到了 Unix 和网络编程领域，成为软件领域广泛接受的一种术语，直至又影响到了 Rust，这就是 tx 的由来。我们来看一下代码：

8. 使用 Mutex 在线程间共享数据

前面，我们学习了线程间的通信技术，当我们在线程中传递一个“值”时，一旦它通过 tx.send() 送走之后，当前线程就再也不能使用这个值了，因为它的所有权已经被转移到接收方那里去了，因此，从所有权的角度观察，线程间通信算是一种“单一所有权”模式，显然，在多线程编程中，我们会在另外一些场景中期望数据是可以被多个线程共享的，也就是“多所有权”模式，这就需要使用 Mutex<T> 了。

Mutex 是 mutual exclusion 的缩写，中文称：互斥器，也就是说，任意时刻，它只允许一个线程访问某些数据（这是多线程环境共享数据时必要保证，否则就会出现数据竞争）。为了访问 Mutex 中的数据，线程首先需要通过获取 Mutex 的 锁（lock）来表明其希望访问数据。锁是 Mutex 数据结构 中的一个组成部分，它记录着谁有数据的排他访问权。因此，Mutex 就是通过锁机制来保护数据的。

提到 Mutex 就不得不提一个笔者熟悉的 Java 中的 synchronized，它的本质也是通过“锁”来控制同步的，不过，两者还是有些区别，Mutex 明显是针对数据设计的多线程锁，而 Java 的 synchronized 更像是“锁住执行过程”，它是对某个对象/代码块施加的互斥访问锁。下面我们看一个 Mutex 的简单示例：

10. Send 和 Sync

Send / Sync 是 Rust 描述“类型具有何种线程安全能力”的两个基础 marker trait。它们没有任何方法需要实现，仅仅是起标记作用。以下是对两种类型的说明：

  • Send：这个类型的值可以安全地把所有权 move 到另一个线程（在线程间移动值）

  • Sync：这个类型的值可以安全地被多个线程并发访问（在线程间传递不可变引用）

Send 和 Sync 可以理解成两种不同的“跨线程通行证”：

  • 这个值能不能被送到另一个线程？看它有没有实现 Send；

  • 这个值能不能在多个线程中通过 &T 共同访问？看它有没有实现 Sync。

也就是说：

  • 实现了 Send 的类型可以参与到这类操作中： thread::spawn(move || ...) 和 tx.send()

  • 实现了 Sync 的类型可以在多个线程中安全地共享其引用： &T

Send 和 Sync 其实是一个有一些抽象又有一些深刻的话题，放在本文中展开不太合适，我们将会在另一篇文章中专门讨论它们。
