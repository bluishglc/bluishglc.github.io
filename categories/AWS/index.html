如何连通私有子网中的 MSK / Kafka 集群？

原创付费分类：AWS发表于：2024-04-16阅读用时：4 分钟 (约 607 字)阅读：0
MSK 集群通常建在私有子网中，本地使用 Kafka GUI 客户端访问很不方便。由于 MSK 是托管服务，Broker 无法 SSH 登录，连接地址又包含多台 Broker，作者尝试 SSH Tunnel 端口转发未能成功。本文改用专门的 Kafka 端口转发工具 Kafka Proxy：在公共子网的堡垒机上安装并启动代理服务，通过 --bootstrap-server-mapping 参数为每个 Broker 配置映射，再在本地的 Offset Explorer 中填写对应的 Broker List 即可连接。测试表明，映射中暴露给远端的主机名和端口必须提供，否则本地客户端无法连接。

云上计算实例的存储盘通常可以在线扩容，本文以 AWS EMR 节点为例记录完整步骤。文章先总结 EMR 的磁盘分配规则：根卷挂载在 /，第二块盘分为固定 5GB 的 /emr 和其余空间的 /mnt，用户追加的磁盘依次挂载到 /mnt1、/mnt2 并自动加入 HDFS。随后介绍用 lsblk、df、parted 查看磁盘、分区与挂载情况，再按“磁盘扩容、分区扩容、文件系统扩容”的顺序操作：在控制台扩大 EBS 卷，用 growpart 扩展分区，ext4 用 resize2fs、xfs 用 xfs_growfs 扩展文件系统；只有一个分区的 xfs 盘可由 xfs_growfs 一步完成。

配置 AWS AD Connector 时最常见的是网络问题。AD Connector 是 Active Directory 的代理，虽为托管服务，仍会在所选的两个子网中各分配一个 IP。即便它与 AD 服务器同在一个 VPC，仍可能报 Unable to reach，原因是创建时无法为其选择安全组，这两个 IP 不在任何安全组中，默认的内网全开规则对其无效。解决方法是显式配置安全组规则，且 DNS 53、Kerberos 88、LDAP 389 三个端口必须同时开放 TCP 与 UDP，共 6 条规则。
