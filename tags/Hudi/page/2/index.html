Flink 读取 Kafka 消息写入 Hudi 表无报错但没有写入任何记录的解决方法

原创付费分类：Hudi发表于：2024-01-31阅读用时：7 分钟 (约 1041 字)阅读：0
用 Flink 读取 Kafka 中的 CDC 数据写入 Hudi 表时，常会遇到作业正常运行、没有报错，但 Hudi 表里迟迟没有数据。原因在于 Flink Hudi Connector 的设计：流式写入时，只有到达 Checkpoint 才会触发提交，而全程使用 Flink SQL 时默认不会启用 Checkpoint，因此永远不会有记录落地。解决方法是开启 Checkpoint，文中给出了配置示例。此外，查询 Hudi 表时对应的 collect 作业可能因缺少 hive-exec.jar 报错，作者建议直接安装 Flink Hive Connector 来解决。

Hudi 在写入和更新数据时会严格控制文件大小，避免产生大量小文件，这一机制称为 File Sizing。本文是「探索 Apache Hudi 核心概念」系列第二篇，借助 Notebook 考察 COW 表和 MOR 表：COW 表中小于小文件阈值（默认 100MB）的文件会在下次写入时参与合并，单个文件不超过 120MB；MOR 表的 Log File 只有大小上限，没有小文件阈值。文章还解释了默认配置下首批插入为何切出多个小文件：首次提交没有历史元数据，Hudi 只能按默认 1KB 的记录大小估算，可用 hoodie.copyonwrite.record.size.estimate 指定。
