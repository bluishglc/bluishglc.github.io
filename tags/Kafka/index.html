Flink: Could not find any factory for identifier kafka/jdbc/hive implements DynamicTableFactory 根治方法

运行 Flink 应用时常遇到 Could not find any factory for identifier kafka 等错误，且打成 uber-jar 时必定出错，单独把 Connector 的 Jar 放到 lib 下则正常。根源在于 Java 的 SPI 机制：各 Connector 通过 META-INF/services 下的同名文件注册自己，打包时这些文件会相互覆盖，导致大量实现没有被注册。解决方法是在 maven-shade-plugin 中配置 ServicesResourceTransformer，以追加方式合并这些声明文件。

Flink CDC 写入 Kafka 时，Sink 表该用 kafka 还是 upsert-kafka，json 还是 debezium-json？四组测试表明：kafka 加 debezium-json、upsert-kafka 加 json 可以工作，另两种组合会报错。kafka connector 不能回放 changelog，只能靠 debezium-json 如实记录变更；upsert-kafka 会把 changelog 回放为最新状态，只能配普通 json。二者在 Flink SQL 中看起来没有差别，但前者在 Kafka 中保留完整变更记录，后者只有最新状态。

Flink 读取 Kafka 消息写入 Hudi 表无报错但没有写入任何记录的解决方法

原创付费分类：Hudi发表于：2024-01-31阅读用时：7 分钟 (约 1041 字)阅读：0
用 Flink 读取 Kafka 中的 CDC 数据写入 Hudi 表时，常会遇到作业正常运行、没有报错，但 Hudi 表里迟迟没有数据。原因在于 Flink Hudi Connector 的设计：流式写入时，只有到达 Checkpoint 才会触发提交，而全程使用 Flink SQL 时默认不会启用 Checkpoint，因此永远不会有记录落地。解决方法是开启 Checkpoint，文中给出了配置示例。此外，查询 Hudi 表时对应的 collect 作业可能因缺少 hive-exec.jar 报错，作者建议直接安装 Flink Hive Connector 来解决。
