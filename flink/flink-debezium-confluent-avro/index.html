Flink 集成 Debezium Confluent Avro ( format=debezium-avro-confluent )

原创付费分类：Flink发表于：2024-01-26阅读用时：18 分钟 (约 2682 字)阅读：0

本文介绍的场景是：使用 Kafka Connect 的 Debezium MySQL Source Connector 将 MySQL 的 CDC 数据 （Avro 格式）接入到 Kafka 之后，通过 Flink 读取并解析这些 CDC 数据，其中，数据是以 Confluent 的 Avro 格式存储的，也就是说，Avro 格式的数据在写入到 Kafka 以及从 Kafka 读取时，都需要和 Confluent Schema Registry 进行交互，从而获取 Schema 信息，本文讨论的就是在这一场景下，Flink 读取这些消息的方法。

1. 两种 Confluent Avro Format 的差异

首先，我们需要注意，在 Flink 中与 Debezium、Avro 、Confluent Schema Registry 有关的 Format 其实有两种，我们一定要注意它们之间的差别：

名称 关键配置 文档 说明
Confluent-Avro Format 'value.format' = 'avro-confluent' 文档 Avro 格式，Schema 由用户自定义，同时集成了 Confluent Schema Registry
Debezium Confluent Avro Format 'format' = 'debezium-avro-confluent' 文档 Avro 格式，Schema 是 Debezium CDC 结构，同时集成了 Confluent Schema Registry

两者差别在于：如果我们使用 'value.format' = 'avro-confluent' 配置来读取 Debezium 的 CDC 数据，是可解析的，Flink 并不会报解析相关的错误，但是，对应的字段都是提取不到值的，基本都显式的是 Null，原因就在于，这种 format 至多能帮助用户将原生的 Debezium CDC 结构解析出来，而不能将其进一步转换为数据表的结构。原生的 Debezium CDC 结构是这个样子的：

也就是说：它解析出来的结构应该是：一个 before 的复合结构，下面是四个字段，after 和 其他字段同理，而不是一条单纯的 表格数据 。

使用 'format' = 'debezium-avro-confluent' 则相当于在 'value.format' = 'avro-confluent' 的基础之上，进一步地对上述解析出来的原生的Debezium CDC 结构进行处理，抽取各个字段的数据，形成了单条记录的格式，这样就能和 Flink SQL 定义的表格结构匹配上，从而提取每条记录的字段值了。

显然，我们要使用的是 Debezium Confluent Avro Format。

2. 生成 Confluent Avro 格式的 MySQL Debezium CDC 数据

测试 Flink 集成 Debezium + Avro + Confluent Schema Registry，必须得先能生成对应的数据，本文使用的方法是：安装一个 Docker 版本的 MySQL ，在 Kafka Connect 上安装 Debezium MySQL Source Connector 和 Confluent Avro Converter 两个插件，启动一个 Confluent Schema Registry ，然后向一个 Kafka 集群推送 采集的 CDC 数据，启动后，使用 《查看 Avro 格式的 Kafka 消息（启用了 Confluent Schema Registry ) 》 一文介绍的方法查看获取到的原生的 CDC 数据。
