C++ 引入第三方库(三)：使用 CMake 导入

原创付费分类：C++发表于：2026-04-07阅读用时：14 分钟 (约 2068 字)阅读：0

使用 CMake 导入库其实应该称为：使用 CMake 将第三方库安装到 CMake 的 install 目录下。解释一下：首先，CMake 有着与 Maven 类似的 install 机制，通过 cmake --install 命令可以将本地 项目 安装到 CMAKE_INSTALL_PREFIX 目录下，这个 CMAKE_INSTALL_PREFIX 是一个变量，用户可以手动设定，如果不显示设置，它在 Windows 下的默认路径是： C:/Program Files (x86)/${PROJECT_NAME} ，也就是说，默认情况下， C:/Program Files (x86) 类似于 Maven 的 %USERPROFILE%/.m2/repository 目录。

另一方面，为了和 CMake 生态集成，大多数的第三方库会主动提供一组符合 CMake 规范的配置文件（一组 .cmake 文件），当第三方库通过 cmake --install 在本地安装之后，就会在安装目录中生成这些文件，CMake 可以通过这些文件自动定位库的头文件和库文件，如此一来，用户只需在项目的 CMakeLists.txt 里使用 find_package 声明一下， CMake 就能自动找到库的相关资源，而不必再向像 方式二：手动导入库和头文件 那样明确指出头文件路径和 链接 库路径，这种导入方式就是使用 CMake 导入，即：通过 CMake 将第三方库以 CMake 的管理形式安装到本地。

使用 CMake 导入库的方法被认为是仅次于包管理器的一种现代化的 C++ 包引入机制，不过，由于CMake 的安装是从源码编译开始的（只有经过源码编译后才能得到关键的 xxxConfig.cmake 文件），这大大削弱了这种方式的便捷性。这和 Maven 的 install 有一个很大的不同，Maven 的 install 只需要 Jar 包和 pom.xml 就能把一个库安装到 repo 中，但 CMake 只能从源代码编译开始。本文我们以 spdlog 这个库为例，完整地演示一下如何使用 CMake 导入第三方库。

1. 工作原理

通过 CMake 导入第三方库的工作原理可简单概括为：让库自己提供一个符合 CMake 规范的文件，把它的包含的头文件和库文件的存放位置提供一下，再让 CMake 能自动找到这个文件，那么用户就不用像方式三那样再手动指明头文件存和链接库的路径了。

实现上述目标，主要靠 find_package 命令和 xxxConfig.cmake 文件。find_package 会在以下几个约定的位置根据提供的包名查找一个名为 <PackageName>Config.cmake 的文件：

优先级 路径类型 示例
1 通过变量指定路径 set(<PackageName>_DIR "/path/to/pkg-dir") [^1]或 -D<PackageName>_DIR=...
2 系统默认路径 /usr/local/，C:/Program Files (x86)/
3 环境变量 CMake 会查找 PATH、CMAKE_PREFIX_PATH 或 CMAKE_FRAMEWORK_PATH 等环境变量对应的安装路径
4 模块路径 首先在 CMAKE_MODULE_PATH 变量定义的路径下查找 Find.cmake 文件，最后在 CMake 安装目录中搜索

找到后，在这个 <PackageName>Config.cmake 文件包含着如下若干重要信息：

  • 头文件目录在哪里

  • .lib 文件在哪里

  • Debug 用哪个 lib

  • Release 用哪个 lib

  • 依赖哪些其他库
