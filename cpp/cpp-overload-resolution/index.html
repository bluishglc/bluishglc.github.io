C++ 重载解析规则

原创分类：C++发表于：2026-03-17阅读用时：16 分钟 (约 2463 字)阅读：0

当我们定义了一组重载函数，然后在别处视图调用其中的一个时，因为重载的函数名称是一样的，你不能像调用普通函数那样直接区分它们，而是要靠参数列表来进行区分，这个“确定多个重载函数中调用的是哪一个”的过程叫：重载函数“匹配”或重载函数“确定”。当调用时传入的参数数量和 类 型严格一一匹配时（也就是所谓的“精确匹配”）），自然不会是一个复杂的问题，真正考验人的情形是：当类型不直接匹配但是经过“自动”发生的各种类型转换后又能匹配成功的情形，这需要我们了解详细的匹配规则：

C++ 重载函数的匹配机制是按以下五级规则逐一尝试：

精确匹配 🠚 “类型提升”匹配 🠚 “标准转换”匹配 🠚 “用户定义类型转换”匹配 🠚 省略号匹

最先在哪一个规则下找到匹配的目标函数就直接认定匹配成功，结束后面的匹配工作，即使后续规则中还有匹配上的函数也不会考虑，因为它们的优先级低于率先匹配上的规则，而如果在匹配的规则下有两个或两个以的函数，就会报错，因为有歧义性，无法确定唯一的目标函数。

特别地，在 “用户定义类型转换”的匹配过程中，还有一种看上去像是“复合转换”的规则，即：

一次可选的“标准转换” 🠚 “用户定义类型转换” 🠚 一次可选的“标准转换”

但这其实不是一种真的复合规则，也不和前面的五级匹配规是相矛盾，只是因为用户定义类型本身就是复合类型，在通过它的构造函数或类型转化符转换时，传入的参数或返回值本身就会多一层类型提升或标准转化的过程，使得它看上去像是一种复合规则而已，这个我们后面会详细解释。

1. 精确匹配

参数个数、类型完全一致，即为精确匹配，这自然是第一种要试图匹配上的情况，目标函数被匹配上时也是“显而易见”的，不需要额外的分析。

2. “类型提升”匹配

类型提升就两种：

  • 整型提升
    将 bool、char、unsigned char、short、unsigned short 转换成 int 类型

  • 浮点提升
    将 float 转换成 double 类型

3. “标准转换”匹配

所谓“标准转换”是指 C++ 内置的隐式转换规则，不需要程序员显示地使用 cast 进行强制类型转换 一样可以编译通过的类型转换（即：与“标准转换”相对的是“强制转换”），例如： int a = 1L 是不会报错的。标准类型转换的规则很多很细，具体可以参考 《C++语言参考：标准转换》 ，本文简单概述一下。标准转换有如下几种：

  • 整型间的转换

    各种整型数据之间的相互转换，非常多的组合，基本上在“bool、char、unsigned char、short、unsigned short int”这些整型之间，除了转换为 int 时数据类型提升外，其他类型之间的转换都是“标准转换”。

    备注：类型转换和类型提升的区别在于：提升不会改变值的大小和精度，是安全的扩展，标准转换可能安全（int 🠚 long)，但也可能会被截断或改变符号（long 🠚 int，int 🠚 unsigned int)，因此编译器在重载匹配时会认定提升优先级高于类型转换。

  • 浮点类型间的转换

    最常见的就是 double 🠚 float，注意：从（float 🠚 double 是类型提升）

  • 整型和浮点类型间的转换

    例如：int 🠚 double 或 double 🠚 int

  • 指针转换

    由于指针可以指代变量、函数、对象，所以指针转换的情况有些“琐碎”，这里只列举三种典型情况：

    • 子类指针 🠚 父类指针

    • 任意对象指针 → void *

    • nullptr 转换

  • 布尔转换

    任何算术类型或指针都可转为 bool，逻辑是：

    • 非0值或非nullptr 🠚 true

    • 0 和 nullptr 🠚 false

  • const 转换

    将普通型转换为 const 修饰的类型是允许的，但是反过来是不行的，道理和父、子指针转换一样：只能将“宽泛”的转换为“严格”的，这不会带来潜在的问题或风险，但反过来就不可以。

4. “用户定义类型转换”匹配

以上转化都是围绕基本类型的转换规则，也都是由编译器自动识别和转换的。涉及到类类型时，C++ 也提供了转换机制，但因为类类型是由用户定义的，所以它们的转换规则也是由用户来定义的，定义的方式有两种：

5. 省略号匹配

省略号匹配自然是最后一个选项，因为它“太宽泛”了，不检查参数个数和类型，自然匹配上的几率会大幅提升。不过，要谨慎使用省略号，除非是在一些明确知道如何处理各种数量和类型参数的情况下。

6. 伪“复合规则”

回应文章开头提及的所谓“复合转换”，我们要单独把“用户定义类型转换”匹配所谓的“复合规则”拿出来再详细地解读一下：

一次可选的“标准转换” 🠚 “用户定义类型转换” 🠚 一次可选的“标准转换”

如前所述，这个规则与五级匹配规则并不矛盾，也不算是一种真的复合规则，而是因为用户定义类型本身就是复合类型，在它们的构造函数和类型转换符的参数中会牵涉到基本类型，在执行构造函数和类型转换符的过程必然会再牵涉一次基本类型的标准转换，而又因为转换后，用户定义类型还能适用指针转换或const转换这种针对类类型的转换，所以又会多一次转换，这个过程其实是“很自然”的，如果梳理开，程序员并不会觉得奇怪，唯一需要锻炼的是：知晓并习惯这种“三联”类型转换。下面我们一些例子，第一个例子是：一次类型提升 + 一次用户定义类型 + 一次const转换，解释一下：如果标准转换可以，那类型提升更可以，我们在上面的规则描述中没有刻意强调类型提升：
