C++基础：const 的五种用法和含义

原创分类：C++发表于：2026-02-03阅读用时：16 分钟 (约 2347 字)阅读：0

C++中的 const 可以出现在五种不同的位置，尽管 const 有只读、不可修改的语义，但是在它出现的每一个位置上，结合其所处的具体位置都有更具体的含义和作用。以下是具体说明：

引用的基础常识：引用在定义时就必须 初始化 ，完成和“初始值”的绑定，且不能在被重新绑定到别的对象上！也就是说，并不存在 int& const r = x; 这种形式的 const，因为：r天然就是 const 的了。

3.1. 不可变的值

演示const和引用的关系我们不能再使用基础类型了，因为“通过一个基础类型的引用去修改一个值”其实是“把引用指向的变量赋了新值”，这个测试根本测试不到 const ！

这里有一个tricky的地方哈： 上述const只是限制了：不能通过r来修改值，但是x并不是const的，所以我们仍然可以通过x来修改值 ！然后，恰恰是const引用的这种特质，满足了对接口调用的“理想约束”：

  • 传递引用而不是拷贝值，保证了性能

  • const约束确保函数不能修改传入的变量/对象，规避各种“不守规矩”造成的麻烦

📌 因此： const 引用就成了 C++ 接口设计（大量方法签名）广泛采用的形参形式！

4. 修饰函数参数

const修饰的函数参数在C++中是最常见的，前面也已经剧透了一下，因为**使用“const引用”类型的函数参数是现代 C++ 接口设计的标准默认选择！**看一个示例：

被广泛采用而成为最佳实践是有原因的：

1. 使用引用形参，避免了值拷贝，性能高

2. 使用const修饰，又避免了在函数体内对传入对象的“误修改”（因为对象是引用传递过来的，一但允许改动就是直接作用到本尊身上了）

这里补充一下 C++ 参数传递的基础知识：

  1. 如果函数的参数（形参）是引用类型，它会绑定到对应的实参上（函数将操纵的就是实参本身），简称：引用传递

  2. 如果函数的参数（形参）是非引用类型，C++会复制一份实参的值附给形参（函数将操纵的就是实参的拷贝），简称：值传递

当然，const 引用也可以应用到函数返回值上，只是这种做法不太常见了，因为这样是把约束施加到调用方了，这在编程里不是常见的情形。

像isbn这类成员函数在 C++ 中有一个专有名词： 常量成员函数 （const member function）,指的就是在方法名和方法体中间加了一个const 关键字 的成员函数，它暗示：这个成员函数不会修改对象本身的任何值。

最后，既然吐槽了C++的const成员函数，简单回顾一下 Java / Scala 的实现策略：在这个问题上，它们和 C++ 的解决思路完全不同，所有 Java 根本没有对等的机制，在 Java 里如果不想让一个成员变量被改写，就声明为 final!这算一层防护，如果允许在类内部改写，而不允许在外部改写（这是最常见的情形），那就只提供getter不提供setter。还有一类类似的情形就是不可变类了，每次变更都返回一个新对象（但不一定是完全拷贝），到了Scala就进化大大量引入Immutalbe类了。
