C++基础：预处理器和头文件包含

原创分类：C++发表于：2026-01-31阅读用时：16 分钟 (约 2439 字)阅读：0

首先说明： 预处理 器和头文件包含是C++的两种特性，它们之间有一些联系，但是独立的机制，本文组织在一起讲是因为：使用头文件和编写头文件经常会使用到一些预处理器指令，放在一起介绍有助于理解整体的逻辑。

1. 预处理器

我们先说 预处理器（preprocessor） ，所谓的“预处理器”其实是指的一组“指令”，这些指令会指导C++在（编译之前的）“预处理”阶段做一些准备工作。它之所以被称为“预”处理器，就是因为它在 编译器 工作之前工作！C++的这种“预处理”机制是从C继承而来的，作用就是：在编译器工作之前先执行一段指令，从源代码文件层面改写一部分内容（作为Java等高级语言程序员来看，这种机制有一点“原始”）！比如： #include 指令就是让预处理器用指定的文件内容替换 #include 。

预处理器包含多种指令：define、undef、include、if、ifdef、ifndef、else、elif、endif、line、error、pragma，既然预处理器是在编译前工作的，所以，预处理器实际上操控的是 源代码 文件，一般有以下几种操控能力:

  • 有条件编译源文件的某些部分（由 #if、#ifdef、#ifndef、#else、#elif 和 #endif 指令控制）。

  • 替换文本宏，同时可能对标识符进行拼接或加引号（由 #define 和 #undef 指令与 # 和 ## 运算符控制）。

  • 包含其他文件（由 #include 指令控制并以 __has_include 检查 (C++17 起)）。

  • 引发错误（由 #error 指令控制）

下面我们详细介绍头文件、 文件包含 和防止重复定义这三种机制，它们会使用到几个最常用的预处理器指令。

2. 分别编译（seperate compilation)和头文件

现代语言编写的程序通常是以class的粒度组织到多个源文件中的，不同的类之间需要相互对方的方法，这就涉及到在编译时怎么找到目标类或方法以判断当前的调用是否符合目标类或方法的声明。在这一问题的解决方法上，C++和 Java 使用了完全不同的解决方案，也是Java程序员因为找不到对等的语言特性而对C++的头文件感觉“陌生”和“困惑”的原因。

我们先说C++的解决方案，貌似是一种更符合“直觉”的会被首先会想到的方案：分别编译！源代码文件（类）之间的相互依赖是错综复杂的网状关系，也包括相互依赖关系（A、B之间相互调用对方），我们不能也不应该让编译器去解析这种依赖关系并安排出编译顺序，即使我们赋予了编译器这种能力，在遇到A、B类相互调用对方的情况时，这种方案也是行不通的，所以 C++使用 的方法是：把类和方法的声明提取出来，放到一个独立的文件中，把类的实现写到另一个文件中，在所有需要使用到这个类或方法的程序代码里，引入一变它的声明文件，让编译器知道这个类或方法的“接口规范”即可（我们说，类和方法的声明就是一种“接口”，一种调用方和被调用方的“契约”），目的是让编译先通过！等编译完，现通过一个链接(link)操作，把它们链接在一起，生成exe文件！

正是因为C++使用了分别编译机制，才促使了类和方法的声明与实现进行了分离，进而催生了一次性声明类或方法的“头文件”以及使用这些头文件的“文件包含”机制。

3. 一个分支问题：什么Java不需要头文件？

然后，我们再回过头来看一下Java的解决方案，首先，我们得清楚：在Java中对应“分别编译”机制的 并不是 包机制！Java的包机制其实对应的是C++的命名空间+访问控制，而Java不需要头文件的根本原因在于：Java能通过 --classpath 一眼看到程序所有的类！压根不存在“每个文件独立编译看不到别的文件”的问题，但这里还是要近一步说明，因为这不能解释java在将源文件(.java)编译成字节码文件(.class)的过程中是如何获取目标类和方法声明的？实际情况是：Java 不是“不需要声明”，而是把“声明”放进了 .class 文件的元数据里。编译器在编译某个 .java 文件时，直接读取其他类的 .class 文件中的“结构信息”，而不是源码。所以，整合到一起：Java不需要头文件的原因是：

Java能通过 --classpath 一眼看到程序所有的类！压根不存在“每个文件独立编译看不到别的文件”的问题
在源文件(.java)编译成字节码文件(.class)的过程中，遇到依赖的类或方法时，Java不是找源代码，而是读取目标 .class 文件的元数据，这些元数据包含了类和方法的声明。

5. 头文件保护（header guard)：防止重复包含

使用文件包含机制会遇到一个普遍的问题：头文件在多处被包含，就会导致里面的内容被重复定义，产生冲突。实际上，一个头文件中的内容应该是全局执行且仅一次的，也就是：声明应该只有一次！这就带来一个问题：各处都需要包含头文件以便编译通过，但是头文件中的指令、程序全局只应该执行一次，这就需要“条件控制”指令了：

  • #define 指令把一个名字设定为预处理变量；

  • #ifdef / #ifndef 指令检查当前预处理变量是否已定义，满足条件才会进入它们和 #enfif 包围起来的预定义内容（和 shell 中的 if...fi 类似）
