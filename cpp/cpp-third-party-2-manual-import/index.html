C++ 引入第三方库(二)：手动导入库和头文件

原创分类：C++发表于：2026-04-06阅读用时：7 分钟 (约 1048 字)阅读：0

尽管这已不是现代 C++ 项目引入第三方库的主流方式了，但算是一种“拖底”方式吧，同时也是一种“原始”的方式，通过这种方式，我们还能体会到 target_include_directories 和 target_link_libraries 最本真的用途，这也是我们这个示例程序的另外一个展示目的。

在决定使用此形式引入第三方库之前，首先要去第三方库的官网查看一下它有哪些发行包，官方并不一定会针对每一种平台都提供发行包，这一点在 Windows 平台上特别突出，很多库都只提供 MinGW 版的发行，而没有 MSVC 版的，例如 curl 就是如此，如果不使用包管理器，就只能从源码编译了。

本文我们选择以 sqlite3 为例进行演示和讲解，选择它的原因在于一是它的官网有现成的二进制发行包（本文使用 MSVC 版） ，另一个原因是引入 sqlite3 的包要比其他直接提供 .lib 文件的库还要“多绕一道弯”，说明性更丰富一点，下面就开始实际操作。

1. 下载发行包

一般来说，第三方库的发行包必定包含二个文件夹，一个放头文件的 include ，另一个是放库文件的 lib ，下载后解压到一个合适的目录就结束了，后面是工程的 CMake 配置。

sqlite3 有一点不同，它的头文件和库文件没有放在一起，分别下载。首先，从 https://www.sqlite.org/sqlite3.h 下载得到头文件，然后打开官方下载页面： https://www.sqlite.org/download.html ，选择下载： sqlite-dll-win-x64-3510300.zip ，这是库文件

我们前面说过，这是最能体现 target_include_directories 和 target_link_libraries 两个 CMake 命令功能的场景，因为这里引入第三方库的方法是最原始的，没有 xxxConfig.cmake 一类的机制影响，我们看到的都是最实际的动作：

  • target_include_directories 把 sqlite 的头文件存放位置加入到项目的“头文件搜索目录”中，使得在代码中可以使用 #include <sqlite3.h> 的形式引用它的头文件，而不用写成 #include "C:/Lib/sqlite/include/sqlite3.h"

  • target_link_libraries 把原始的链接库文件加到项目中，以便在链接时能找到 sqlite。这里直接给出的是库文件路径，而不是像 Qt 里经常出现的 target_link_libraries(my-app PRIVATE Qt6::Widgets) 那样，这种“直给”方式更能让人体会到 target_link_libraries 的原始功能。
